# 云服务器部署 · 从零开始

> 目标：把项目部署到一台公网服务器上，让任何人打开一个网址就能用。
> 全程大约 30 分钟，其中大部分时间是在等命令执行完。
>
> 如果你只想在同一个 WiFi 内让队友访问，不需要买服务器，见文末「附：不花钱的方案」。

---

## 为什么必须买服务器

现在的做法是每个人在自己电脑上跑一份服务。问题在于**每份服务背后是一套独立的 MySQL 数据库**：

```
你的电脑  ──>  你的 MySQL     ┐
                              ├── 两套数据，互相看不见
队友的电脑 ──>  队友的 MySQL   ┘
```

所以队友搜不到你、你也收不到他的消息。这不是程序 bug，是架构决定的。

只要**所有人访问同一个地址**，问题就消失了：

```
你的电脑  ─┐
           ├──>  服务器上的 MySQL（唯一一份数据）
队友的电脑 ─┘
```

---

## 第一步：买一台服务器

### 选购建议

| 项目 | 建议 |
| --- | --- |
| 厂商 | 腾讯云 / 阿里云 / 华为云的**轻量应用服务器**（最简单，控制台最傻瓜） |
| 配置 | **2 核 2G**、系统盘 40G 起。本项目很轻，1 核 2G 也能跑 |
| 镜像 | **Ubuntu Server 22.04 LTS**（或 24.04）。⚠️ 选「系统镜像」，不要选「应用镜像」 |
| 地域 | 选离你和队友最近的（如上海、广州），延迟低 |
| 带宽 | 3M 起步够用；主要影响图片/视频上传下载速度 |

### 省钱：学生认证

- 腾讯云「云 + 校园」、阿里云「高校计划」都有学生优惠，价格通常几十元一年
- 需要学信网学籍验证，认证一次管一年

买完之后，在控制台能看到**公网 IP**（形如 `123.45.67.89`），后面到处要用。

---

## 第二步：连上服务器

### 方式 A：网页终端（最省事，推荐）

云厂商控制台里找「登录」「远程连接」「WebShell」之类的按钮，点一下会打开一个网页终端，直接就是命令行，不用配任何东西。

### 方式 B：用自己的终端 SSH

Windows 打开 **PowerShell**（不是 cmd）：

```powershell
ssh ubuntu@你的公网IP
```

- 腾讯云 / 华为云 Ubuntu 的默认用户名一般是 `ubuntu`
- 阿里云可能是 `root`
- 密码忘了就在控制台「重置密码」

> 第一次连接会问 `Are you sure you want to continue connecting?`，输入 `yes` 回车。

连上之后，你会看到类似 `ubuntu@VM-0-1-ubuntu:~$` 的提示符，说明已经在服务器里了。

---

## 第三步：把代码传到服务器

### 方式 A：git clone（推荐，之后更新代码方便）

```bash
# 克隆到你希望放代码的位置
sudo mkdir -p /var/www
cd /var/www
sudo git clone <你的仓库地址> heritage
sudo chown -R $USER:$USER /var/www/heritage
cd /var/www/heritage
```

如果是私有仓库，clone 时会要求输入 GitHub 用户名和 Personal Access Token（不是登录密码）。

### 方式 B：本地打包上传（git 用不熟就用这个）

在**你自己的电脑**上，项目根目录执行：

```powershell
# 打包（排除体积大又没用的目录）
tar -czf heritage.tar.gz --exclude=node_modules --exclude=.git .

# 上传
scp heritage.tar.gz ubuntu@你的公网IP:~/
```

然后回到**服务器**上：

```bash
sudo mkdir -p /var/www/heritage
sudo tar -xzf ~/heritage.tar.gz -C /var/www/heritage
sudo chown -R $USER:$USER /var/www/heritage
cd /var/www/heritage
```

> **注意**：`.env` 不在代码包里（含密钥，不会提交到仓库）。
> 不用担心，下一步的脚本会自动帮你生成一个带随机密钥的 `.env`。

---

## 第四步：跑两个脚本

这两条命令是整个过程的核心，其余都是准备工作。

```bash
cd /var/www/heritage

# ① 装环境：Node.js + MySQL + PM2，建库，生成 .env，放行防火墙
sudo bash deploy/setup-server.sh

# ② 部署应用：建表、导入数据、用 PM2 启动、健康检查
bash deploy/deploy.sh
```

第一条脚本大约跑 3–5 分钟（要下载安装 MySQL）。结束时你会看到：

```
============================================
  环境安装完成
============================================
  数据库:  heritage   账号: heritage
  配置:    /var/www/heritage/.env
```

第二条脚本结束时：

```
============================================
  部署完成
============================================
  访问地址: http://123.45.67.89:3000/MainPage.html

  健康检查:
    {"status":"ok","uptime_seconds":8,"db":"connected", ...}
```

看到 `"db":"connected"` 就说明数据库连上了。

> 两个脚本都可以**重复执行**。以后更新代码后，再跑一次 `bash deploy/deploy.sh` 即可。
> `setup-server.sh` 只在第一次需要跑。

---

## 第五步：放行端口（最容易漏的一步）

如果第四步最后给的地址打不开，**99% 是这里没配**。

云服务器有**两道独立的防火墙**，两道都要放行：

### 第一道：云平台的安全组 / 防火墙

在云厂商控制台里：

- **轻量应用服务器** → 「防火墙」→ 添加规则
- **CVM / ECS** → 「安全组」→ 入站规则 → 添加规则

放行这些端口：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| `22` | TCP | SSH 远程连接 |
| `80` | TCP | 网站（HTTP） |
| `443` | TCP | 网站（HTTPS） |
| `3000` | TCP | 本项目默认端口（配了 Nginx 后可以不开放） |

来源填 `0.0.0.0/0`（表示允许任何 IP 访问）。

### 第二道：服务器内部的 ufw

`setup-server.sh` 已经帮你配好了。想确认：

```bash
sudo ufw status
```

---

## 第六步：验证

浏览器打开：

```
http://你的公网IP:3000/MainPage.html
```

能打开就成功了。然后：

1. 打开 `http://你的公网IP:3000/login.html` 注册两个账号（一个选「买家」，一个选「开发者」）
2. 互相加好友、发消息
3. 让队友用他的电脑打开同一个地址，用你注册的账号登录试试

**只要大家打开的是同一个 `http://公网IP:3000`，好友和消息就是互通的。**

## 把我本机现在的数据搬到服务器

部署到服务器后是个全新的数据库，只有 `db:migrate` 导入的演示账号。如果你想把**本机已经积累的账号、好友、消息**搬过去：

在**你自己的电脑**上导出（Windows 的 Git Bash / cmd）：

```bash
mysqldump -u root -p --no-create-db --no-tablespaces heritage > heritage.sql
```

上传：

```bash
scp heritage.sql ubuntu@你的公网IP:~/
```

在**服务器**上导入：

```bash
sudo mysql heritage < ~/heritage.sql
pm2 restart heritage-api
```

> ⚠️ **不要两边同时运营**。数据一旦分叉（本机又新增了消息、服务器上也有新消息），合并会非常麻烦。
> 决定用服务器之后，就让大家统一访问服务器地址。

## 日常更新代码

在服务器上：

```bash
cd /var/www/heritage
git pull                         # 拉取最新代码
bash deploy/deploy.sh            # 重新部署（会自动重启服务）
```

常用运维命令：

```bash
pm2 status                  # 查看运行状态
pm2 logs heritage-api       # 查看实时日志（Ctrl+C 退出）
pm2 restart heritage-api    # 重启服务
pm2 stop heritage-api       # 停止服务
```

设置开机自启（执行一次即可）：

```bash
pm2 startup                 # 它会打印一条 sudo 命令，复制执行
pm2 save
```

## 可选：绑域名 + 开启 HTTPS

### 绑域名

1. 在域名服务商买域名，做 A 记录解析到你的公网 IP
2. **国内服务器用国内域名必须备案**，否则 80/443 会被拦截 —— 这是政策要求，绕不过去
3. 不想备案的话，直接用 `http://公网IP:3000` 也能正常用

### 开 HTTPS

域名解析生效后：

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp /var/www/heritage/nginx.conf.example /etc/nginx/conf.d/heritage.conf
sudo nano /etc/nginx/conf.d/heritage.conf     # 把 server_name 改成你的域名
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d 你的域名              # 自动申请证书并配置 HTTPS
```

配好后访问 `http://你的域名` 就是网站首页，不用再带 `:3000`。

## 常见问题对照表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 浏览器一直转圈 / 连不上 | **安全组没放行端口** | 回第五步，放行 `3000` |
| 启动报「无法连接 MySQL」 | 数据库没启动或密码不对 | `sudo systemctl start mysql`；检查 `.env` 里的 `DB_PASSWORD` |
| 启动报「JWT_SECRET 还是模板占位符」 | `.env` 是手动从模板复制的，没改 | 重跑 `sudo bash deploy/setup-server.sh`（会自动生成随机密钥） |
| 访问 `/shop/` 返回 404 | 商城构建产物缺失 | 正常情况下仓库里已带 `feiyi-ecommerce/dist`，确认代码拉全了 |
| 上传大文件失败 | Nginx 上传限制或安全组 | 见 `nginx.conf.example` 里的 `client_max_body_size 220m` |
| 页面能开但接口全 401 | 改完 `.env` 没重启 | `pm2 restart heritage-api` |
| 服务跑一会儿就没了 | 没配开机自启 / 没 pm2 save | 执行 `pm2 startup` 后按提示操作，再 `pm2 save` |

查看真实报错：

```bash
pm2 logs heritage-api --lines 50
```

## ⚠️ 上线前必须做的事

部署到公网后，**任何人都能访问你的网站**，下面几件事不做会出事：

1. **删掉或改掉演示账号密码**
   导入的 `testuser` / `testdev` / `newuser` / `newdev` 密码都是 `123456`。
   别人拿到就能登录，甚至登进开发者后台。
   建议：进数据库把这些账号删掉，或改成强密码。

2. **不要提交 `.env`**
   里面有 JWT 密钥和数据库密码。仓库的 `.gitignore` 已经忽略了它。

3. **停止跟踪 `database.json`**
   这个文件目前仍在仓库里，含有真实的密码哈希。执行一次：
   ```bash
   git rm --cached database.json
   git commit -m "停止跟踪本地数据文件"
   ```

4. **确认 `.env` 里的 `JWT_SECRET` 是随机生成的**
   脚本会自动生成。如果是手动配置的，用这个生成：
   ```bash
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```

## 附：不花钱的方案（局域网共享）

如果只是答辩演示、或者团队成员都在同一个 WiFi 下，**不用买服务器**：

1. 选一台**常开**的电脑当服务器
2. 在上面正常把项目跑起来（`.env` 里 `HOST=0.0.0.0`，默认就是）
3. 查它的局域网 IP：
   ```bash
   ipconfig        # Windows，看「IPv4 地址」，形如 192.168.1.5
   ```
4. 其他人浏览器访问 `http://192.168.1.5:3000/login.html`

**注意两点**：

- 当服务器的那台电脑不能关机、不能休眠
- Windows 防火墙要放行 3000 端口（管理员 PowerShell）：
  ```powershell
  netsh advfirewall firewall add rule name="heritage" dir=in action=allow protocol=TCP localport=3000
  ```

局限：只在同一个局域网内有效。出了这个 WiFi（比如队友回宿舍用自己的网）就连不上了。
